企业财务智能报销与审核编排系统

项目类型：AI Agent 应用系统  |  技术栈：FastAPI + React + CrewAI + 百度OCR

一、项目概述

一句话定位：基于 CrewAI 多 Agent 编排的企业报销系统，实现发票 OCR 识别、AI 合规校验和智能审批路由。

真实问题与应用场景

痛点具体表现
人工审核效率低财务逐张核对发票，耗时耗力
合规检查易遗漏重复报销、金额不一致难以人工发现
流程不透明员工不知道报销单卡在哪个环节
数据统计困难部门费用汇总依赖手工 Excel

目标用户：企业员工、财务人员、部门主管、系统管理员

四、AI 工具使用与系统编排

1. CrewAI 多 Agent 编排

Agent职责输入输出
OCR识别 Agent从发票图片提取结构化信息发票图片/PDF发票号、金额、日期、销售方
合规校验 Agent执行4项合规检查发票数据 + 报销单校验结果（通过/警告/不通过）
审批路由 Agent根据规则确定审批节点报销金额、部门、校验结果审批链路（财务/主管/管理员）

2. 百度 OCR API

  • 增值税发票识别：提取发票代码、号码、含税金额、税额、销售方等
  • 通用文字识别：兜底方案，处理火车票、出租车票等非标发票
  • PDF 转图：使用 PyMuPDF 将 PDF 发票转为图片后识别

3. AI 合规校验规则

检查项说明不通过处理
发票真实性发票号码格式校验、销售方信息完整性阻断提交
重复报销全库检索相同发票号，关联已审批/打款记录阻断提交
金额一致性发票含税金额与报销金额对比，差额>0.01元触发警告，可提交
OCR置信度识别置信度<70%触发人工复核提醒警告，可提交

五、存在的问题与风险

问题影响应对措施
OCR 对非标发票识别率有限火车票等结构化提取不完整通用OCR兜底 + 人工复核
百度 OCR API 调用限制高并发场景可能触发限流可加本地缓存和异步队列
数据库使用 SQLite生产环境并发性能有限可迁移至 PostgreSQL
缺少电子发票验真无法对接国家税务总局查验平台后续可集成验真API

六、下一步计划

  1. 电子发票验真：对接国家税务总局发票查验平台，验证发票真伪
  2. 操作审计日志：记录所有关键操作，支持追溯和合规审查
  3. 差旅申请关联：出差申请单与报销单关联，实现差旅全流程管理
  4. 数据库升级：SQLite 迁移至 PostgreSQL，支持更高并发
