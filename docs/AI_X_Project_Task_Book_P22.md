## 二、真实问题与使用场景

### 真实问题描述

中小企业在财务报销流程中普遍面临以下痛点：

- **效率低下**：员工需手动填写纸质报销单、粘贴发票，财务人员逐张核对发票真伪、金额是否合规、是否存在重复报销，整个流程耗时且易出错。
- **审批不透明**：报销单流转过程缺乏可视化追踪，员工不清楚当前审批进度，沟通成本高。
- **合规风险**：人工审核难以面面俱到，发票真伪难辨、重复报销难以发现、金额匹配校验依赖人工经验。
- **教学需求**：软通动力教育科技有限公司需要一套真实的企业级AI应用案例，用于培训学员理解AI在企业财务场景中的落地方式。

本系统通过 OCR 发票识别 + AI 合规校验 + 多级审批编排，将传统人工报销流程升级为智能化的数字工作流。

### 目标用户/服务对象

| 角色 | 职责 | 受益方式 |
|------|------|----------|
| 企业员工 | 提交报销申请、上传发票 | 告别纸质流程，随时提交、实时追踪 |
| 财务人员 | 审核发票、审批报销、标记付款 | AI辅助校验减轻核对负担，批量操作提升效率 |
| 部门经理 | 二级审批下属报销 | 在线审批，无需纸质签字 |
| 系统管理员 | 用户管理、分类管理、报表统计、预算管控 | 数据驱动决策，一键导出报表 |
| 软通动力教育 | 需求方与教学案例使用者 | 获得可展示的AI落地教学案例 |

### 使用场景

1. **报销创建**：员工出差或办公采购后，登录 Web 系统创建报销单（金额、类别、日期、支付方式），上传发票照片（支持 JPG/PNG/PDF 格式）。
2. **智能识别**：系统自动调用百度 OCR API 识别发票关键信息（发票号码、金额、日期、销售方、购买方），并展示识别结果。
3. **AI 合规校验**：规则引擎自动执行四项校验——发票真实性、是否重复报销、发票金额与报销金额是否匹配、OCR 识别置信度评估——并生成可视化校验报告。
4. **审批流转**：员工提交后，报销单依次进入财务审批 → 经理审批（可根据预算和金额范围配置跳过）→ 标记付款。
5. **实时追踪**：各角色可在仪表盘查看报销状态流转（草稿 → 待财务审 → 待经理审 → 已通过 → 已付款），支持批量审批和退回操作。
6. **报表分析**：管理员可查看按状态、类别、部门的报销汇总统计和月度趋势，支持 CSV 导出。

## 三、目标成果与最小可交付成果（MVP）

### 最终目标成果

一个功能完整的企业财务智能报销 Web 应用系统，包含四个角色端：

- **员工端**：报销创建与编辑、发票上传与管理、报销记录查看、回收站（软删除恢复）
- **财务端**：待审批列表、发票详情查看、AI 校验结果展示、单条/批量审批、退回、标记付款
- **经理端**：待审批列表、单条/批量审批、审批链规则跳过配置
- **管理端**：用户 CRUD 管理、报销类别管理、部门预算管理、报销标准与审批链配置、多维度统计报表、CSV 数据导出

**技术交付物**：
- FastAPI 后端完整代码（Python，含 Swagger 自动API文档）
- React 前端完整代码（响应式设计，含角色路由守卫）
- 数据库初始化脚本与种子数据
- 一键启动脚本（macOS .command 文件）
- 系统部署说明文档

### 最小可交付成果（MVP）

可演示的 Web 应用原型，覆盖报销核心闭环：

1. 员工可创建报销单并上传发票（JPG/PNG/PDF）
2. 百度 OCR 自动识别发票关键信息
3. AI 规则引擎执行四项合规校验并可视化展示结果
4. 财务人员可查看待审批列表、审批或退回报销单
5. 报销状态可视化流转（草稿 → 待财务审 → 待经理审 → 已通过 → 已付款）
6. 基于 JWT 的角色级权限控制

### 主要 AI 工具/工作流

| 工具/技术 | 用途 | 使用方式 |
|-----------|------|----------|
| **百度 OCR API**（增值税发票识别） | 发票图片自动识别提取发票号、金额、日期、销售方等信息 | 通过 HTTP API 调用，支持真实 OCR 和模拟数据降级 |
| **PyMuPDF (fitz)** | PDF 格式发票转图片，供 OCR 处理 | 后端文件处理管道中调用 |
| **CrewAI 多 Agent 框架** | 编排 OCR 识别 Agent、合规校验 Agent、审批路由 Agent 的协作流程 | 定义 Agent 角色、Task 任务、Crew 流程管道 |
| **AI 合规规则引擎** | 四项结构化校验：发票真实性检查、重复报销检测、金额匹配校验、OCR 置信度评估 | 后端 ValidationService 中实现，结果聚合为 valid/warning/invalid 三级 |
| **AI 校验结果可视化** | 前端展示每条校验规则的通过/警告/不通过状态及中英文说明 | React 组件渲染校验详情面板 |
| **OpenCode / Cursor** | AI 辅助编码、代码审查、Bug 修复 | 贯穿整个开发周期 |
